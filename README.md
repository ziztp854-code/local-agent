# الوكيل المحلي

وكيل عربي خاص يعمل على جهازك عبر LM Studio. يستخدم Gemma 4 E4B للمحادثة
واستدعاء الأدوات، وNomic Embed للبحث الدلالي عند الحاجة. التبعية الوحيدة هي
`tkinterdnd2` لدعم سحب الملفات من Windows.

## تطبيق Windows

شغّل LM Studio أولًا، ثم انقر مرتين على `LocalAgent.pyw` أو افتح النسخة المستقلة:

```text
dist\LocalAgent.exe
```

تتضمن الواجهة العربية:

- اختيار مساحة العمل والنموذج والجلسة.
- أوضاع القراءة والبرمجة وأوامر المضيف.
- محادثة لا تتجمد أثناء عمل النموذج.
- بث الرد لحظيًا مع صندوق قابل للطي لتفكير النموذج وسمة داكنة.
- ردّ فعل hover لطيف على كل الأزرار (يُحسب لحظيًا من لون الزر فيبقى صحيحًا بعد تبديل السمة)،
  ونظام تصميم مركزي للمسافات والزوايا وتوليد ظلال الألوان في `theme.py`.
- إرفاق حتى أربع صور للنموذج المرئي.
- سحب الصور أو مجلد مساحة العمل وإفلاتها داخل النافذة.
- صفحة تكاملات لإعداد MCP وذاكرة Nomic الدائمة.
- مكتبة مهارات قابلة للبحث والمعاينة داخل التطبيق.
- لوحة أوامر شاملة بزر `Ctrl+K` للوصول السريع لكل أزرار التطبيق.
- قوالب مطالبات جاهزة (لخّص المشروع، اقترح تحسينات، ابحث عن أخطاء…) تُدرج بنقرة واحدة.
- شريط إحصاءات حي للجلسة: عدد الطلبات واستدعاءات الأدوات والردود المكتملة والمتوقفة.
- تصدير المحادثة كاملة بصيغة Markdown من الزر أو لوحة الأوامر.
- تذكّر الإعدادات تلقائيًا: الثيم ومساحة العمل والنموذج والوضع والجلسة، محفوظة ذريًا
  في `%LOCALAPPDATA%\local-agent\settings.json`.
- تلخيص ذكي لمساحة العمل عند البدء: عدد الملفات والمجلدات واللغات الغالبة مع اقتراحات،
  دون قراءة محتوى الملفات وبتخطي `.git` و`node_modules` وملفات الأسرار.
- إظهار نشاط كل أداة داخل المحادثة بسطر مميز، ومؤقت حي لزمن الرد في شريط الحالة.
- فحص تلقائي لاتصال LM Studio عند البدء وعند «تطبيق وبدء»، وبالمفتاح `Ctrl+L` أو من
  لوحة الأوامر؛ عند الفشل تظهر خطوات التشغيل كاملة داخل المحادثة (حمل النموذج ثم
  `lms server start` ثم أعد الإرسال). الفحص للخادم المحلي فقط.
- نافذة موافقة تعرض الفرق أو الأمر كاملًا، مع جعل الرفض هو التركيز الافتراضي.
- صفحة لمراجعة تغييرات الوكيل دون Git.
- نقاط استعادة وزر تراجع يطلب موافقة مستقلة.

## مسار التفويض والمراجعة

في وضعي «برمجة» و«برمجة + أوامر المضيف» يظهر خيار **مسار مفوّض**. عند تفعيله
تنتقل المهمة عبر أربع بوابات ظاهرة في تبويب «التغييرات»:

1. ينفّذ العامل المهمة ويعدّل الملفات بعد موافقات الكتابة المعتادة.
2. ينشئ التطبيق وكيلًا جديدًا بصلاحيات قراءة فقط لمراجعة الفرق بصورة مستقلة.
3. يكتشف التطبيق أمر الفحص المحافظ للمشروع (`unittest` أو `pytest` أو `npm test`
   أو `cargo test` أو `go test`) ويعرض موافقة مستقلة قبل تشغيله.
4. لا يتفعّل زر «اعتماد النتيجة» إلا إذا وافق المراجع ونجح أمر الفحص.

تشغيل الفحوصات التلقائي يحتاج وضع «برمجة + أوامر المضيف». في وضع «برمجة» فقط
تظهر بوابة الاختبارات على أنها لم تُشغّل، وتبقى النتيجة مقفلة بدل افتراض النجاح.
الاعتماد يسجّل قرارك النهائي؛ أما كل كتابة وأمر فتبقى خاضعة لموافقتها التفصيلية
كما كانت من قبل، ويمكن استخدام «تراجع عن آخر تعديل» لاستعادة اللقطة السابقة.

لبنائها مجددًا عند تعديل المصدر:

```powershell
py -3.12 -m pip install -r requirements.txt
py -3.12 tools/make_icon.py
py -3.12 -m PyInstaller --noconfirm --clean --onefile --windowed `
  --collect-all tkinterdnd2 --name LocalAgent --icon assets/app_icon.ico `
  --add-data "assets;assets" --distpath dist --workpath build `
  --specpath build LocalAgent.pyw
```

أيقونة التطبيق مولّدة بلا تبعيات من `tools/make_icon.py` (معيّن ◆ طيني-نحاسي على
مربّع حبر داكن) وتُحفظ في `assets/`. أعد تشغيله لو غيّرت التصميم.

استخدم Python 3.12 للبناء؛ حزمة Tkinter في Python 3.14 الحالية لا تُضمّن بيانات Tcl
بشكل صحيح في PyInstaller على هذا الجهاز.

## التشغيل الآمن للقراءة

```powershell
lms load google/gemma-4-e4b --gpu max --context-length 16384 --parallel 1 --ttl 900 -y
lms server start --port 1234 --bind 127.0.0.1
python agent.py --workspace "C:\Projects\my-project"
```

لطلب واحد:

```powershell
python agent.py --workspace "C:\Projects\my-project" --prompt "لخص المشروع"
```

## وضع البرمجة

```powershell
python agent.py --workspace "C:\Projects\my-project" --coding --session my-project
```

يضيف هذا الوضع:

- إنشاء ملف نصي جديد دون طمس ملف موجود.
- استبدال نص يظهر مرة واحدة بالضبط.
- معاينة unified diff وSHA256 ثم طلب موافقة مستقلة لكل تعديل.
- كتابة ذرية ورفض العملية إذا تغيّر الملف بعد المعاينة.
- `review_changes` لمراجعة كل فروق العملية حتى خارج مستودعات Git.
- حفظ آخر المحادثات اختياريًا خارج المشروع في `%LOCALAPPDATA%\local-agent\sessions`.

لا توجد أداة حذف، ولا دفع أو دمج أو نشر آلي.

## المهارات المحلية

يرتبط التطبيق بحزمة المهارات العلمية الموجودة في:

```text
D:\UserData\Downloads\claude-scientific-skills-main\claude-scientific-skills-main
```

يفهرس التطبيق 177 مهارة علمية داخل مجلد `scientific-skills` (قواعد بيانات، أدوات
تحليل، كتابة علمية، تصور…). لتغيير الحزمة ضع مسارًا بديلًا في متغير البيئة
`LOCAL_AGENT_SKILLS_ROOT`. يبحث الوكيل في الأسماء والأوصاف، ثم يقرأ أقل مهارة
مطابقة ومواردها النصية عند الحاجة. تظهر الحزمة كاملة في تبويب «المهارات».
الحدود: 250 مهارة، و8MB إجمالي للتعليمات، و128KB لكل ملف مهارة أو مورد،
وسقف 24KB لتعليمات المهارة الواحدة في نتيجة الأداة (مع إحالة إلى الموارد).

تعليمات المهارات غير موثوقة ولا تمنح صلاحيات جديدة. التطبيق لا يشغّل سكربتات
الحزمة تلقائيًا، ولا يفتح HTML نشطًا، ولا يقرأ ملفات ثنائية، ويرفض المسارات
الخارجة وروابط إعادة التوجيه والملفات الأكبر من الحدود. أي كتابة أو أمر يظل
خاضعًا لأدوات الوكيل وموافقتك الحالية. يجب أن يبقى مسار الحزمة موجودًا لتعمل
المهارات.

## الصور والذاكرة الدائمة

الصور تعمل فقط مع نموذج يدعم الرؤية مثل Gemma 4 E4B. يقبل التطبيق PNG وJPEG
وWebP وGIF بحد أربع صور و20 MiB إجمالًا، ولا يحفظ Base64 أو أسماء الصور في السجل.
يتحقق من ترويسة الملف وحجمه ولا يفك الصورة؛ لذلك استخدم صورًا موثوقة لتجنب ملفات
الصور المصممة لاستنزاف وحدة فك الترميز داخل خادم النموذج.

يمكن استخدام أي Qwen يقدمه خادم OpenAI-compatible محلي بتغيير اسم النموذج. لا
يحمّل التطبيق ملفات `safetensors` أو `GGUF` مباشرة، والنماذج النصية لا تستقبل الصور.

ذاكرة المحادثة الدلالية مغلقة افتراضيًا. لتفعيلها اختر اسم جلسة ثم فعّلها من
صفحة «التكاملات»، أو استخدم:

```powershell
python agent.py --workspace . --session demo --semantic-memory
```

تُحفظ النصوص محليًا في ملف SQLite واحد قابل للفحص بأي عميل تحت
`%LOCALAPPDATA%\local-agent`؛ لا تستخدمها لحفظ أسرار. أما متجهات البحث داخل
ملفات المشروع فتُخزن دون النص المصدر. الاسترجاع هجين: تشابه متجهي دمج مع
فهرس معجمي FTS5 عبر RRF، وكل ذاكرة تحمل مصدرها وتاريخها، وتُستبدل الحقائق
المصحَّحة بالإحلال بدل الحذف.
افتح اسم الجلسة في نسخة واحدة من التطبيق فقط؛ التخزين المحلي ليس مهيأً لعدة كاتبين
متزامنين على الجلسة نفسها.

## MCP والمتصفح وقواعد البيانات

اختر `mcp.example.json` من صفحة «التكاملات» لتشغيل Playwright MCP. سيطلب التطبيق
موافقة قبل تشغيل الخادم ثم موافقة أخرى قبل كل استدعاء أداة. تشغيل خادم MCP ليس
معزولًا، وقد يصل إلى الملفات أو الشبكة بصلاحيات حسابك منذ لحظة التشغيل؛ استخدم
خوادم موثوقة فقط، لأنه قد يقرأ أو يعدّل أو يحذف بيانات قبل أول استدعاء أداة.
تُكتشف قائمة أدوات الخادم عند الاتصال؛ أعد تشغيل التطبيق إذا غيّر الخادم أدواته أثناء الجلسة.

يمكن إضافة خادم `stdio` أو خادم `http`/`sse` محلي إلى الملف نفسه، وتبديل حالته من
الواجهة. تُرفض الروابط غير المحلية والتحويلات وبيئة proxy. لا توجد قاعدة بيانات
مفترضة أو بيانات اعتماد مضمّنة. ضع الأسرار في متغيرات البيئة واكتب مرجعًا مثل
`${DATABASE_TOKEN}` بدل القيمة داخل JSON.

## تشغيل الاختبارات والأوامر

تشغيل أوامر المضيف منفصل. ويمكن من الواجهة اختيار Docker أو Podman لتغليف الأمر
بلا شبكة وبربط مساحة العمل فقط؛ لا يُعامل WSL كـ sandbox ولذلك لا يظهر كخيار. قبل
التفعيل، عيّن `LOCAL_AGENT_CONTAINER_IMAGE` إلى صورة محلية مثبتة بـ
`name@sha256:<64 hex>`؛ لا يُسمح بـ tag قابل للتغير.

```powershell
python agent.py --workspace "C:\Projects\my-project" --coding --allow-host-commands
```

يعرض الوكيل الأمر كقائمة `argv` ويحذر ثم يطلب موافقة لكل تشغيل. يستخدم التنفيذ
`shell=False`، ويمنع `cmd` وPowerShell وملفات batch، ولا يمرر أسرار البيئة، ويحد
المهلة والمخرجات. مع ذلك، البرنامج الموافق عليه يعمل بصلاحيات المستخدم وقد يقرأ
خارج المشروع أو يصل إلى الشبكة. لا تستخدم هذا الخيار مع مشروع غير موثوق. الموافقة
تفشل تلقائيًا عند غياب طرفية تفاعلية. المهلة تضبط العملية الأساسية؛ بلا sandbox قد
ينشئ برنامج خبيث عملية منفصلة تستمر، لذلك يبقى هذا الخيار للمشاريع الموثوقة فقط.

لضبط الحدود:

```powershell
python agent.py --workspace . --max-steps 8 --max-tool-calls 16 `
  --max-history-turns 6 --timeout 120 --command-timeout 120 `
  --max-command-output 64000 --max-tool-result-bytes 48000
```

## ذكاء الوكيل الهيكلي

جودة النموذج المحلي تبقى كما هي، لكن الطبقة الهيكلية حوله ترفع نتائجه عمليًا:

- **منهجية تفكير صريحة**: محثّ النظام يوجّه النموذج للتفكير داخل وسم `<thought>` قبل كل
  خطوة (تحليل ← خطة ← تنفيذ ← تحقق)، ويظهر التفكير في لوحة خاصة دون أن يدخل الجواب.
- **استمرارية التفكير بين خطوات الأدوات**: يرى النموذج خطة خطوته السابقة داخل الطلب الواحد،
  ويُنظّف السجل المحفوظ من أي تفكير.
- **عدم التخمين**: قاعدة صريحة «لا تدّعِ معرفة بلا دليل؛ اقرأ قبل أن تجيب»، وإجابة نهائية
  بصيغة: خلاصة ← تفاصيل ← خطوة تالية.
- **تصحيح ذاتي محدود**: عند فشل أداة يتلقى النموذج تلميحًا لتصحيح الوسائط وإعادة المحاولة
  مرة واحدة فقط، ثم تغيير الطريقة أو شرح السبب.
- **حارس التكرار الفاشل**: إذا كرّر النموذج استدعاء الأداة نفسه بالوسائط نفسها بعد فشله،
  يُقصَّر المسار فورًا بإعادة توجيه أقوى بدل إعادة تنفيذ الجدار نفسه واستنزاف ميزانية الأدوات.
- **استدعاء دلالي استباقي**: عند تفعيل الذاكرة يطابق الوكيل نص الطلب بالتضمين تلقائيًا
  ويحقن أعلى الذكريات المطابقة (فوق عتبة تشابه) كسياق غير موثوق، لأن النموذج المحلي الصغير
  نادرًا ما يطلب الذاكرة بنفسه؛ ويبقى `recall_memory` متاحًا للبحث الأعمق. يفشل بهدوء دون تعطيل الطلب.
- **سياق ممتد بذكاء**: عند تجاوز حد الجولات تُلخَّص الأدوار القديمة في ملاحظة سياق موجزة
  (240 حرفًا لكل دور، 12 دورًا كحد أقصى) تُحقن في الطلب فقط، ويبقى السجل المحفوظ نظيفًا.

## الحماية والحدود

- وضع القراءة هو الافتراضي، ووضع البرمجة تفعيل صريح.
- كل المسارات نسبية ومحصورة داخل `--workspace`؛ الروابط وNTFS reparse points محظورة.
- يمنع ملفات الأسرار الشائعة مثل `.env` والمفاتيح الخاصة، ويخفي مجلدات الأسرار و`.git`.
- يقبل خادم النموذج المحلي فقط ويرفض الخوادم البعيدة وإعادة التوجيه.
- يقرأ ويكتب نصوصًا حتى 64KB، ويحد الملفات والجولات واستدعاءات الأدوات والاستجابات.
- لا يشغّل Git ضمن الوضع الافتراضي؛ `review_changes` يراجع تعديلات الوكيل دون Git.
- هذه الأدوات تحاكي سير عمل وكيل برمجة؛ جودة التفكير تظل جودة النموذج المحلي وليست GPT-5.6 Sol.
